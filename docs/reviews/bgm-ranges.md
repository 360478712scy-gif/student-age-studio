# BGM 范围、延续与静音

2026-09-20，Codex。已完成本地修改与 Windows 定向验收，尚未发布；线上仍为 1.3.11.6。

## 行为

- 新范围默认不选对话；全选按钮再次点击取消全部。既有范围打开时显示已有成员。
- 起止框支持对话 ID 后三位或完整 ID，包含两端；同后三位重复时要求完整 ID，非法/不完整范围不落入旧范围。输入期间目录/正文异步刷新不丢失输入。
- `0 · 延续` 是不换曲，保留之前的音乐或静音，不在范围结束时自动停止。
- `静音` 使用本地生成的两秒 PCM WAV（全零采样、循环），与其他 BGM 共用范围和保存规则。文件跟随 Mod；重复点击复用音频 ID/文件，导入不顺便保存正文草稿。
- 缩短/取消范围清除旧指令；编辑当前事件范围时保留其他事件的成员。支持撤销；只在换曲入口写原生 `TalkCfg.audio`，后续为 0；跨 0 / 未配置间隔后重用同曲不再重复启动，独立事件入口和不同曲分支汇合保留必要指令。

## 根因与修复边界

旧前端默认选择到事件末尾，并在整个所选范围写非零 audio；缩短未保存范围时没有清除已排除句的指令。改为原生导出统一计算换曲边界，编辑草稿不再给每句写重复指令。

Windows 实际预览另暴露：分段正文未就绪时，Player.select 异步返回，而 openStoryPreview 立即 play 了上一个 scene。表现为中途开始预览先播放旧音乐，下一句才正确。现在先加载所选句再开始，忽略期间已切换/取消的请求，不加载无关正文。

截图所述“白雨编辑器看不到”的原始 Mod 未提供，不能确认其单独原因。原版后续句 audio=0 本就表示延续，不应为了在每句显示音乐而写入重复换曲。游戏语义依据私有 research/editor/View.Evt.NewTalkView.cs 的 BlackBg 与 PlayAudio；未运行真实游戏业务流程。

## 验收

- 新后端 7 项：原生入口/重复保存/重开、缩短/清除/0、外部原生字段修改优先、分支与独立入口、跨 0/间隔同曲不重播、静音资源真实采样/去重/冲突保护、非法数据保护；本机与 Windows 均通过。
- Node：bgm-editor（范围、无效 ID、跨事件、延迟预览入口）、bgm-playback（音乐/0/同曲/静音/换曲播放器不重建）；既有 scene-engine 35 组及首帧回归通过。
- 本机 Python 全套 243 项：首次有 1 项因系统 Python 缺 numpy 无法运行，改用已有依赖运行时复跑 test_user_chains 12 项通过；合计 238 通过、5 平台跳过。
- Windows 11 原生 WebView2，隔离 99 句 Mod：默认空选、全选/取消、001–030、缩为001–010、031–040静音、041–060延续、061–070换曲、草稿保护、保存与重开通过。磁盘仅第001/031/061句有非零 audio；其余为0。
- 实际编辑器剧情预览：翻句普通 BGM 同一播放器时间 0.211→0.416 秒；从041句开始延续静音，翻句同一播放器时间0.208→0.412秒，均未重播。静音 WAV 全零采样已直接验明。
- Windows 为隔离源码窗口和实际磁盘 Mod 验证，不冒充新完整客户端或真实游戏验收。原始证据保留 output/bgm-range（不入发行包）。
