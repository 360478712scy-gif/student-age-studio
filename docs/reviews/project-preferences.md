# 订阅模组读取范围与默认模组（Codex，2026-09-20）

## 根因与实现

后台 MediaWarmup 原先每 30 秒遍历所有本地及订阅模组，每轮 scan_media 两次，冷缓存会生成图片缩略图、完整解码校验和像素去重；已缓存也仍遍历全部文件。模组条件配置目录默认请求全部模组。这些开销确实随订阅数量增长；未取得反馈者的现场跟踪，不将其认定为唯一原因。

1. 后台仅预热当前打开模组；原版素材和用户自选素材目录保留。未打开模组的缓存不主动验证或解码；已有缓存继续保留供主动访问。
2. 设置里的订阅忽略名单在项目发现前过滤，同时阻断直接访问、素材目录、条件和编号查询。应用前保护前端草稿；服务端等待正在执行的请求、后台预热和图片哈希结束，清理派生缓存后刷新页面释放前端状态。正常请求仍并发，保存校验的文件指纹没有 TTL。
3. 移除对应分段缓存、预热条目、像素索引、校验和配置对象。保留其他模组可追溯的预览缓存；旧版没有来源信息的散落缩略图会重建。忽略名单仅保留恢复开关所需的名称与路径。失败清理留待下次启动重试；从不删除订阅文件或取消 Steam 订阅。
4. 默认模组偏好持久化；启动只读取该偏好，优先于上次打开记录，无效时回退到可用模组。条件配置按所选来源请求，默认当前模组，仍可主动选择全部。

## 验收

- 8 项新增后端检查：忽略后不读取文件、恢复读取、保存重建 Store、原文件字节不变、内存/磁盘缓存回收、仅允许订阅模组、无效默认项、当前模组预热、嵌套目录排除、普通请求并发及清理等待、清理中断后恢复。
- Windows 11 后端全套 250 项通过（2 项平台跳过）；最终清理调整后复跑，并补充清理中断重试，共 8 项通过。本机全套 250 项仅系统 Python 缺 numpy 的 1 项不能运行，使用已有依赖 Python 复跑对应 test_user_chains 12 项通过（5 项平台跳过）。
- Windows 11 原生 WebView2，2 个本地与 40 个订阅模组：默认选择、覆盖上次打开记录、订阅搜索、忽略与恢复、刷新后保持、过期项目请求 404、未保存草稿保护及条件目录按所选来源请求通过。源码窗口验收，不等于真实用户现场或完整发行 EXE 验收。
- Windows 隔离对照，40 个订阅模组与 2 个本地模组，共 328 张 960×540 图片：全模组冷预热 24.1373 秒，当前模组 8 张冷预热 0.7140 秒；缓存后检查分别 0.1426 / 0.0226 秒。对照执行同一素材预热函数，仅改变其模组范围，不是整个编辑器所有操作的延迟。
