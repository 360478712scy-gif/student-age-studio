# 长时间使用与缓存显示排查

2026-09-19，Codex。基于正式版 1.3.11.1 / main 593440d；本轮对应界面版本 1.3.11.2，兼容更新协议 1.3.12-beta.2；线上发布结果由发布验收记录确认。

## 已确认问题和修复

- 每张已缓存缩略图仍检查整模组修订，持有与普通编辑操作共用的 store.lock。现在只实时核对相关素材定义、来源、路径和目标图片；索引定位条目。保存/导入保持完整实时修订检查，没有加入 TTL。
- 不相关正文保存产生新 revision，旧素材目录此前最多积累 96 份。重读目录时淘汰同一模组失效修订的快照，保留当前可用目录和磁盘缩略图。
- 素材页面每次请求会唤醒全库后台扫描，绕过原 30 秒等待。现在合并自动唤醒，扫描期间及冷却期间不重复触发；手动重试仍可立即唤醒。
- 素材选择窗口关闭后，释放其 DOM、图片、列表、选择状态及回调引用，取消只读请求及图片重试计时器；导入等写操作不会被取消。编辑器草稿和撤销数据不在回收范围。
- Windows 实测发现目录新增文件后，目录指纹可能尚未变化，复用旧文件名会漏掉新增图片。Windows 每次重新枚举文件名，同时保留内容校验及图片缓存；其他平台继续沿用目录指纹复用。

## 可重复验证

证据目录：隔离工作树 output/session-perf（不公开真实模组与素材）。

- 合成 500 张背景、200 个无关配置表：48 张暖缩略图，Mac 同机修复前 1483 ms、修复后 29 ms。计数器记录 server 层配置指纹调用 21696→48；新预览相关文件校验另计，不是全部文件系统调用只有 48 次。
- 同一合成样本 40 次正文变更/目录重开：修复前保留 41 份目录，额外 traced allocations 68.11 MiB；修复后保留 1 份，2.74 MiB。测量期间启用 tracemalloc，目录耗时不能作为普通使用速度。
- Windows 11 NTFS 隔离副本：48 张暖缩略图 98 ms；40 次正文变更/目录重开始终保留 1 份目录，traced allocations 2.75→2.76 MiB。
- Mac 后端 217 项，212 通过/5 平台跳过；Windows 后端 217 项，215 通过/2 平台跳过。Windows 新增文件检测先复现失败，修正后通过；相关配置外部同尺寸修改并恢复 mtime 仍拒绝过期预览，保存冲突仍返回 409。
- Chrome 实际素材选择器组件：50 次打开/关闭、确认与取消、多选结果、未保存草稿、只读请求中止、图片重试计时器清理、关闭回调立即重开均通过。隔离 HTTP 数据，不等同真实游戏素材验收。
- 测试夹具收尾等待自身后台哈希写入结束，避免已删临时目录被后台重建；模拟运行中的测试显式恢复模拟状态。

Windows 11 原生 WebView2：25 轮背景/表情窗口切换通过，检测实际图片 naturalWidth、选择确认/取消、关闭后立即重开、草稿保留与关闭后 DOM 回收。80 张合成背景 + 100 个额外配置；背景打开（包含原版→模组切换）首轮 1994 ms、中位 1054 ms、最大 3840 ms、末轮 853 ms。合成表情图片使用实际资源读取接口，不等同游戏 Live2D 模型的全表情生成验收。测试运行在本机虚拟机，不代表反馈者的硬件。

## 结论边界

反馈截图显示 StudioEngine 约 254 MB、系统内存 51%，没有证据将该用户卡顿归因于内存不足。上面确认的是重复扫描/共用锁以及失效资源积累；“已缓存”不代表请求链路没有等待。没有取得反馈者的运行现场，未复现其完整两三分钟等待，也未做数小时真实游戏模型和全部页面的长时验收。不可据此保证所有卡顿消失或宣称零 bug。
