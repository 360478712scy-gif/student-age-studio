# 工坊设置卡住修复（2026-10-04，1.4.9.3）

## 原因与改动

反馈日志中，1.4.8 的 `POST /api/updates/check` 联网检查耗时 45.3 秒，持有游戏目录锁，使普通请求排队约 45 秒。设置入口又先等待 `game-locations` 和 `cache-settings` 才显示窗口。

- 更新状态、检查和启动下载只使用更新器自身的锁，不再占用游戏目录锁或模组读取策略锁。启用／回退更新继续沿原有串行流程；接口仍校验会话令牌与来源。
- 设置立即显示可关闭的加载状态；重复点击合并请求，刷新只渲染一次。读取失败可重试；关闭后晚到的响应不会重新开窗。
- 更新面板在 `checking` 和 `downloading` 状态轮询，结束后更新按钮与提示；关闭窗口或移除组件后停止请求，迟到旧响应不能覆盖新操作。

## 验证

- 定向 Python 34 项通过：设置响应 2、更新器 28、缓存响应 4。
- Chrome 设置组件回归通过，更新面板 9 项回归通过；含延迟、失败重试、关闭竞态及完成状态。
- Windows 11 x64 Python 3.12.10 + Edge 的实际编辑器与后端：人为阻塞更新连接时，五个设置分类、关闭、普通接口、默认模组写入及实际保存均通过。普通接口约 5–85 ms，默认模组写入约 168 ms，保存约 1.49 秒并核对磁盘正文。
- 设置读取本身延迟时约 271 ms 显示可关闭的加载窗口；晚响应不重开。Windows 更新面板补测使用实际更新器与生产组件，检查结束约 485 ms 自动显示完成状态。

隔离证据位于公开工作树 `output/settings-responsiveness/` 与 `output/settings-open/`。本次未进行原生 WebView／游戏验收。反馈日志中的备份权限、素材读取锁及音乐传输断开是另外的记录，本次没有将它们计作已修复。
