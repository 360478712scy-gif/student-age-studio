## 结论与取舍

| 范围 | 结论 | 融合处理 |
| --- | --- | --- |
| 删除事件保护共用对白 | 适合，必须补齐前端和选项 | PR 只改 Python，前端仍会先删共用对白并提交明确删除列表。两端统一为仅删除所有归属都在删除集合内的对白；仍被保留对白/事件引用的选项一起保护。无事件归属的对白不当作垃圾。 |
| 完整对话表缺行返回 409 | 适合，需兼容明确的配置表替换 | 普通剧情全表提交缺行直接拒绝；用户在表格页面主动删除的记录由该入口明确列入 deletedIds。分段 patch 保存不要求携带完整表。 |
| 磁盘快照回滚 | 适合，需补齐失败分支 | 优先同卷移动已有快照，减少磁盘满时再分配空间；一份文件恢复失败后继续恢复其他文件，明确报告未恢复项和快照位置。不能承诺所有系统故障下必然恢复。 |
| 保存快照最多 20 份 | 适合，需修正清理顺序和范围 | PR 用带随机后缀的名称排序，同一秒内可能误删最新快照；改用日志时间并固定保护当前快照，只清理 committed 状态，保留准备中/回滚失败快照。尊重已有自动清理开关。完整模组手动/自动备份继续沿用原设置。 |
| 清除过期 .pending 备份 | 采用 | 已有跨进程备份锁保护；保留新建、符号链接和未满 24 小时的目录。 |
| 原版 SQLite 空闲关闭、切换/退出关闭 | 适合，PR 空闲实现不完整 | 原实现只有下一次访问才关闭，真正空闲期间仍占句柄。改为短时空闲定时关闭并串行保护读/关闭；同进程重建数据库前主动关读者，文件变化使用实时指纹。 |
| 损坏原版编辑记录容错 | 适合，需补齐 JSON 解析失败和页面入口 | 读模式可提示后打开；损坏 JSON 与结构损坏均覆盖。表列表也使用提示式读取；写模式 owned/preserve/compact 保持严格拒绝，不覆盖坏记录。 |
| 保留编号公开及分配上限 | 采用并补齐前端 | 保留 reservedIds，前端分配备用范围也限制探测次数。它不是跨窗口原子预约协议，保存冲突保护仍不可去掉。 |
| 哈希队列与校验缓存限额 | 采用并调整排队 | 不淘汰尚未完成的队首，满队列时延后新任务，防止频繁刷新造成饥饿；后台/前台共用有锁的校验缓存限额。 |
| BMP/TGA 导入 | 采用，补齐草稿预览 | 文件选择器含扩展名；目标图像先经只转换、不落盘的接口生成 PNG，再显示草稿，保存动作仍由用户原来的流程完成。 |
| 安装目录缓存不可写时回退 | 采用并调整探测 | 使用唯一临时探测文件，避免覆盖固定 `.write-test` 文件；按安装目录记忆结果。 |
| Windows Job 启动降级 | 限制后采用 | PR 把所有 access denied 都当已受监督；仅在分配 Job 失败且已确认当前进程位于已有 Job 时降级。桌面宿主修改需未来完整客户端构建，轻量更新不会送达。 |
| 场景旧入口回溯截断 | 不直接采用原算法 | PR 把重复相同背景也视为边界、跳过换场句自身，还未覆盖 CG 保留人物。保留 1.3.11 正常路径的直接登场来源；只对缺来源的旧状态按原生 apply 重建，确保落到仍生效的登场句，不宣称这条旧状态兜底已消除全部扫描。 |
| JSON 修复预算、路径预解析 | 采用并兼容 1.3.11 | 保留最新逐文件摘要/真实指纹及正文记录保存链路，不把旧 PR 的全量 revision 读取重新合回来。 |

## UI 调整

- 删除事件继续用原确认窗口：准确说明保留共用对白/选项，取消为默认焦点；删除后可能残留的事件跳转如实提示。
- 保存审查沿用两按钮，返回修改为主要/默认操作；不增加确认层级。
- 首步引导允许跳过等待，其他步骤原操作保留。
- 社交删除显示影响数量；目标数字与扩展字段 JSON 错误都能聚焦；BMP/TGA 草稿可见。
- 预览缺图时保留姓名/历史底色，后续重试成功再启用原版框样式。
- 独立子 agent 做代码初审与隔离浏览器复审，发现的问题由主 agent 修正。
