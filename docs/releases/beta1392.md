# 1.3.9.2

修复原版对话在编辑器里“不存在”的问题。此前目录提取只保留原版对话的编号，不保留正文，于是：

1. 原版资源编辑模式打开任何事件都是空的，且每个事件都被标成“与原版事件 ID 冲突”。现在进入事件时按需载入它的原版对话（只载入打开过的事件，不会把整部游戏的对话一次读进来），原版模式下不再显示冲突标记。
2. 模组里覆盖原版事件的记录（事件行在模组里、对话仍是原版）显示“沿用外部对话入口 / 0 句已载入对话”，无法查看。现在这类事件会连带载入它引用的原版对话、选项，可直接查看和修改；改过的句子作为覆盖写入模组，没改的句子不写入。
3. 从“原版剧情事件”点“覆盖到当前模组”后事件是空的。现在覆盖会立即保存并重新打开，事件带着原版对话出现在列表里；覆盖记录即使未修改也会保留。

实现：目录提取时把原版 TalkCfg/OptionCfg 正文另存为缓存目录里的 `original-dialogue-v1.sqlite`（按编号读取，不占内存）；已有目录但没有这个文件的机器会在启动时自动重新读取一次原版配置。事件卡上原来的“⚠ 与原版…冲突”改为中性的“覆盖原版…”说明；自动编号不会再落到已载入的原版对话/选项编号上。

作者 Claude。完成隔离验证：覆盖事件显示并可进入原版对话、未修改保存不写入模组、修改一句只写一句、浏览器覆盖后立即可编辑、原版模式无冲突标记并按需载入；Python 单测全部通过（新增 test_original_dialogue）。未做真实游戏与 Windows/Mac 原生窗口验收。本次为轻量在线更新。

## 同版本追加

- 剧情事件标题旁新增圆形排序按钮，切换按事件 ID / 按事件名称排序（记住选择）。
- 分类标签新增「原版事件」：只列出覆盖原版的事件（原版模式下为全部）。
- 右下角快捷工具新增「合并模组」：左侧多选可编辑模组，右侧实时检查人物重复（同编号不同内容，标出人物名，可选择保留哪个模组）、其他重复记录、同名素材文件及其他问题；「合并模组」会确认后生成一个新模组（内容取并集、冲突按所选保留、素材路径改到新模组），原模组不改动。
- 通知类事件（无对话入口）的卡片标明“仅通知文本，无对话”并显示通知内容。
- 修复一个事件里混进另一个事件对话的问题：编辑记录里残留的“对话归属”（例如某段对话是在打开 A 事件时导入、后来接到了 B 事件）会一直把它同时算给 A。现在以实际连接为准——能从某个事件入口走到的对话只属于那些事件，记录里的旧归属只用来保留尚未接上的孤立段落。
